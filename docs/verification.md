## 실제 Google Drive 연결

`ChatGPT` 폴더에 빈 네이티브 마스터 파일을 생성했습니다. 관리 탭 12개의 모든 헤더가 코드 스키마와 일치하며 2행은 비어 있음을 연결 도구로 다시 읽어 확인했습니다. 헤더 고정/굵게/줄바꿈/연회색 서식도 API에서 확인했습니다. 실제 브라우저 렌더 검증은 도구가 없어 수행하지 않았습니다. 기본 빈 Sheet1은 삭제하지 않았습니다. 마스터에는 실제 여행 데이터나 가상 샘플을 넣지 않았습니다.

초기에는 Codespaces Secrets가 없어 Python API 연결은 미검증이었습니다. 사용자 설정 및 Codespace 재시작 후 두 Secret의 존재와 마스터 ID 일치를 확인했습니다. 키 내용은 출력하지 않았습니다.

2026-10-11 실제 Google Sheets API 연결 결과:

- `travel-db init`: dry_run=true, created_tabs=[] — 기존 관리 탭/헤더 확인 성공, 생성할 탭 없음.
- `travel-db search --table regions --limit 1`: total_matches=0 — 실제 지역 테이블 조회 성공, 현재 데이터 없음.
- `travel-db ingest examples/sample.json`: dry_run=true, committed=false, created=3, skipped=0, queued=0 — 가상 샘플 3개에 대한 입력 계획 검증 성공. 실제 추가 건수는 0이며 샘플을 마스터에 저장하지 않았습니다.

첫 실행은 제한된 네트워크 환경에서 연결 오류가 났고, 승인된 네트워크 접근으로 재실행하여 위 결과를 확인했습니다. Python 서비스 계정의 인증·조회와 입력 dry-run은 검증 완료입니다. 실제 쓰기 권한 및 저장 후 재조회 round-trip은 아직 라이브 검증하지 않았습니다. 별도 테스트 시트의 쓰기 검증과 구분합니다. 인증 설정 절차는 README.md에 있습니다.

## 2단계 당시 후속 범위

지역/카테고리 자동 분류와 유사 중복 후보 검사는 2단계에서 구현했습니다. 대기 승인/거부, 기존 데이터 업데이트와 복구는 3단계입니다. 기존 항목 변경과 중복 후보는 대기열에 남깁니다. 별도 테스트 시트에서 Python 쓰기 round-trip도 검증해야 합니다. Sheets의 다른 편집자와 동시 쓰기를 완전히 격리할 수 없어 한 작업자씩 실행해야 합니다.

출처 URL은 중복 등록하지 않으며 출처 제목/게시자/열람일은 최초 등록값을 보존합니다. 3단계에서는 필드별 근거·확인일을 별도로 관리합니다. 전역 출처 메타데이터 수정은 현재 제공하지 않습니다.

## 2단계 검증

최종 실행 결과: **113개 테스트 통과**. Ruff 린트/형식 검사, git diff 공백 검사, 기존 1.0 및 신규 1.1 예제의 인증 없는 입력 검증이 통과했습니다. 신규 가상 예제의 전체 처리 테스트는 신규 3개·검증 대기 2개와 재실행 멱등성을 확인했습니다. GitHub Actions에도 신규 예제 검사를 추가했으며 원격 CI 실행 결과는 아직 확인하지 않았습니다.

JSON 1.0 회귀 검사를 유지하며 JSON 1.1 자동 분류, 국가/도시의 현지명·별칭·유니코드 처리, 동명 도시 모호성, 힌트/ID 충돌, 분류 사전 및 문맥별 유형 정규화, 신규 지역을 포함한 역순 배치, 잘못된 최종 항목 검증을 검사합니다.

유사 중복 검사는 이름 오타·현지명 교차 일치·주소·좌표 거리·같은 도시 내 세부 지역·동명 원거리 지점 구분·누락 좌표·임계값 경계·후보 정렬/제한·국가 코드·노선의 다른 출발지/도착지·배치 내부 중복을 검사합니다. 후보가 기존 행을 수정하지 않고 원문/근거와 함께 대기열에 보존되며 dry-run은 무변경, 반복 요청은 멱등적임을 확인합니다. 공개 JSON Schema와 런타임 모델 일치도 검사합니다.

2단계 검증에는 메모리/HTTP 테스트 더블과 별도 가상 샘플만 사용했습니다. 실제 마스터에 샘플을 저장하거나 헤더를 변경하지 않았습니다. 1단계에서 확인한 Python 인증·조회·dry-run과 이번 샘플 기반 기능 검증을 구분합니다.

## 3단계 검증

실행 결과: **170개 테스트 통과**. Ruff 린트/형식 검사와 작업 JSON 예제의 인증 없는 형식 검사가 통과했습니다. 작업 JSON Schema와 런타임 계약 일치도 검사합니다. CI에도 작업 예제를 추가했으며 원격 CI 결과는 아직 확인하지 않았습니다.

승인/거부·완성 항목의 재검증·명시적 업데이트·필드별 출처·이전값 및 근거 복구를 구현했습니다. 테스트는 dry-run 무변경, 요청 재실행, 중복 결정 거부, 수정/신규 대상 구분, 출처 누락/잘못된 출처, null 변경, 개인 평가 근거, 전체 DB의 종속 참조, 중복 후보의 명시적 확인, 이력 손상, 후속 변경이 있는 복구 중단, 다른 항목이 사용하게 된 식별키의 복구 거부를 검사합니다. 백업 전체 복원과 생성 취소 삭제는 3단계 범위가 아닙니다.

원자적 실패와 반영 후 응답 유실을 샘플로 재현하여 데이터·결정·출처·이력·영수증이 부분 저장되지 않고 같은 요청 재실행 시 두 번 수정되지 않는 것을 확인했습니다. HTTP 더블로 단일 updateCells/appendCells 배치, 수식 문자열 처리, 빈 행/행 이동 충돌, 1,000행 이후의 정확한 물리 행 위치를 검사했습니다.

2026-10-11 마스터의 **운영 스키마 확장**을 적용했습니다. 기존 관리 탭 12개의 헤더를 연결 도구로 확인하고 dry-run 계획에서 새 탭 두 개만 확인했습니다. Google Drive 연결로 review_decisions와 field_sources를 생성했고 재조회에서 정확한 헤더·빈 데이터 행·고정 헤더·굵게·줄바꿈을 확인했습니다. 관리 탭은 총 14개입니다. 기존 데이터와 기본 Sheet1은 보존했습니다. 실제 여행 데이터나 가상 테스트 샘플은 넣지 않았습니다. 브라우저 화면의 시각적 검증은 수행하지 못해 API 서식 확인과 구분합니다.

Python API의 `travel-db init` dry-run은 created_tabs=[]였고 `travel-db pending --limit 1`은 pending=0, resolved=0을 반환했습니다. pending은 최초 제한 네트워크 연결 오류 후 승인된 읽기 전용 접근으로 성공했습니다. 3단계 당시 새 구조 조회는 검증했고 실제 데이터 수정·복구 후 재조회는 미검증이었습니다. 다음 4단계에서 별도 테스트 Sheets로 검증을 완료했습니다.

- E2E: 사용자 Drive의 전용 테스트 파일. 실제 ID는 개인 설정에서 확인
- 백업 복원: 사용자 Drive의 별도 빈 테스트 파일. 실제 ID는 개인 설정에서 확인

라이브 백업 `/tmp/travel-db-stage4-20261011-backup.json`을 CLI verify-backup으로 다시 검사했습니다. checksum은 `f084216bf54907b5c7d4a51c740850986f851a3d87f7b26f491c000ad32f4fff`입니다. 이 파일은 테스트/백업 자료이며 운영 DB가 아닙니다. 테스트 파일 링크와 재실행 방법은 [4단계 문서](workflows.md)에 있습니다.

Google Drive 연결로 두 파일의 음식점과 승인/거부 셀을 다시 읽어 1000 JPY와 approve/reject 기록을 확인했습니다. 복사된 고정·굵은 헤더 서식도 API에서 확인했습니다. 브라우저 렌더 확인은 수행하지 못했으며, 실제 수천~수만 항목의 부하와 여러 편집자의 동시 쓰기 시험은 수행하지 않았습니다. Sheets 격리 제한과 전역 출처 메타데이터 수정 미지원은 유지합니다. 위 1·3단계의 Python 쓰기/수정/복구 미검증 상태는 이번 별도 파일 E2E에서 해소했습니다.

## 5단계: 운영 점검 및 가상 대량 검증

2026-10-11, Python 3.14.2에서 `audit`를 추가했습니다. 읽기 전용으로 여행 항목/참조 검증과 운영 기록의 기본 형식/연결, 입력함 요청/영수증 충돌을 확인합니다. 잘못된 입력함 봉투는 warning, DB/이력 손상과 요청 충돌은 error입니다. 상세 제한이 있더라도 전체 오류 수/healthy 판정은 유지합니다. 원문·인증 정보는 출력하지 않습니다. 입력함에 승인/수정 요청이 있어도 실행하지 않음을 검사합니다.

샘플 및 독립 메모리 E2E/복원 결과의 점검, 잘못된 해시·시각·JSON·영수증 참조·물리 위치, 손상된 본 테이블 참조, 중복 JSON 키/NaN, 입력함 재입력 충돌, 경고/오류 종료 코드를 테스트했습니다. 입력/작업/조사 모델 변경은 없으며 기존 JSON Schema 일치 테스트를 유지합니다.
